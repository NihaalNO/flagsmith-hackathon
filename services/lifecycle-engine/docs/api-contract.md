# Lifecycle Engine — API Contract (proposal, v0.1)

Proposed mount point in the shared backend: `/api/v1/engine` (to be agreed with Member 1).
Full schema: [openapi.json](openapi.json). Example responses: [`../mocks/`](../mocks) — generated by
running the engine on the sample repositories (`scripts/generate_mocks.py`), so they are real outputs.

All requests/responses are JSON validated by Pydantic (`lifecycle_engine/schemas/`). Unknown fields
are rejected. Timestamps are ISO-8601 UTC.

## Operations

| Route | Request | Response | Mock |
|---|---|---|---|
| `POST /discover` | `DiscoverRequest` | `ScanResult` | `discover.json` |
| `POST /flags/analyze` | `AnalyzeFlagRequest` | `FlagAnalysisReport` | `analysis_new_checkout.json` |
| `POST /lifecycle/evaluate` | `EvaluateLifecycleRequest` | `LifecycleEvaluation` | `lifecycle_evaluation_new_checkout.json` |
| `POST /lifecycle/transition` | `TransitionRequest` | `FlagLifecycle` | `error_transition_requirements.json` (error) |
| `POST /stale/detect` | `DetectStaleRequest` | `StaleDetectionResponse` | `stale_findings.json` |
| `POST /cleanup/plan` | `CleanupPlanRequest` | `CleanupPlanResponse` | `cleanup_plan_new_checkout.json`, `cleanup_plan_legacy_search.json` |
| `POST /cleanup/patch` | `GeneratePatchRequest` | `CleanupPatch` | `patch_new_checkout.json` |
| `POST /cleanup/verify` | `VerifyCleanupRequest` | `VerificationResult` | `verification_ready_new_checkout.json`, `verification_incomplete_legacy_search.json` |

Common request field `repositories: [{repository, root_path}]` — `repository` is the stable id
(e.g. `acme/checkout-web`), `root_path` a local checkout prepared by the backend's GitHub
integration. Paths must be under the service's `allowed_roots`.

## Errors

```json
{ "error": { "code": "transition_requirements_not_met", "message": "...", "details": { "missing_evidence": ["rollout_stable"], "missing_approvals": ["flag_owner"] } } }
```

| HTTP | code | when |
|---|---|---|
| 403 | `path_not_allowed` | repository path outside allowed roots |
| 403 | `commands_not_allowed` | request supplied verification commands (disabled by default) |
| 404 | `repository_not_found` | checkout missing |
| 409 | `invalid_transition` | edge not in the state machine (`details.valid_targets`) |
| 422 | `transition_requirements_not_met` | missing evidence/approvals (`details.*`) |
| 422 | `safety_violation` | override tried to bypass cleanup/retire requirements |
| 422 | `missing_input` | e.g. patch direction cannot be derived |
| 422 | (FastAPI default) | request validation errors |
| 500 | `internal_error` | unexpected failure (no internals exposed) |

## Field guide for the frontend (Member 3)

### `ScanResult` / `FlagReference`
* `references[]` — one per occurrence. Group by `flag_name`; `summary.flags[]` already does.
* `classification` — `confirmed` (show normally), `potential` (show with a "needs review" badge;
  `confidence` < 0.7), `dynamic` (`flag_name` is null; show `argument_expression`).
* `location` — `repository`, `file_path`, `line`, `column` (1-based) for deep links.
  `start_byte`/`end_byte` are internal; ignore them.
* `usage_type` — `boolean_evaluation`, `value_retrieval`, `flag_object_retrieval`, `hook_subscription`.
* `evidence[]` — human-readable reasons for the classification (tooltip material).
* `trait_reads[]` — trait accesses (`trait_key`), not flags.

### `FlagAnalysisReport`
* `branches[]` — `kind`, `polarity`, `condition`, `enabled_path`/`disabled_path` (`excerpt`, `span`,
  `callees`, `rendered_components`). `determinable: false` → show "manual review".
* `fallbacks[]`, `related_symbols[]` (`exclusively_flag_gated: true` = only reachable via the flag),
  `related_tests[]` (`strength` strong/weak).
* `feature_scope` — `full_feature_candidate` | `partial` | `unknown` | `not_referenced`.
* `findings[]` (`is_hypothesis: true` → phrase as "may"), `uncertainties[]`,
  `unresolved_dynamic_references[]`.

### `LifecycleEvaluation`
* `current_state` vs `suggested_state` — the suggestion is never applied (`is_recommendation: true`).
* `transitions[]` — each valid next state with `allowed`, `missing_evidence`, `missing_any_of`,
  `missing_approvals`; drive the "advance" buttons from this.
* `warnings[]` — show prominently (e.g. "100% exposure does not prove the rollout is complete").

### `StaleFlagFinding` (in `StaleDetectionResponse.findings[]`, sorted strongest first)
* `status` — `not_stale`, `insufficient_evidence`, `potentially_stale`, `ready_for_cleanup`, `safe_to_retire`.
* `confidence` (0–1), `score` (net evidence), `cleanup_direction`, `inline_value`.
* `evidence[]` — `direction` supports/opposes/neutral and signed `weight`: render as for/against lists.
* `blockers[]` — why the status is capped. `missing_evidence[]` — what to collect next (`blocks` lists
  which statuses it prevents). `recommended_next_action` — one-line CTA.
* `requires_human_decision` is always `true`.

### `CleanupPlanResponse`
* `plan.recommended_action` — `no_action`, `gather_evidence`, `request_owner_review`,
  `prepare_cleanup_patch`, `request_archive_approval`.
* `plan.statements[]` — `type` fact/hypothesis/recommendation, `evidence_ids` resolve into
  `plan.evidence[]` (show citations).
* `plan.affected_files`, `plan.obsolete_code_paths`, `plan.proposed_changes[]`,
  `plan.risk.overall` + `items[]`, `plan.required_approvals`, `plan.verification_requirements`.
* `plan.llm.status` — `not_configured` / `used` / `unavailable` / `rejected_invalid_output`
  (show an "AI narrative unavailable" note when not `used`; the plan is still complete).
* `patch` — present only when the flag is ready for cleanup.

### `CleanupPatch`
* `files[].diff` — unified diff to render; `files[].edits[]` — per-edit descriptions.
* `status` — `complete`, `partial` (see `manual_steps[]`), `not_generated` (see `notes[]`).
* `follow_ups[]` — newly unused code; suggestions only.

### `VerificationResult`
* `status` — `ready_for_review`, `incomplete`, `failed`; `ready_for_human_review` boolean.
* `test_results[]` / `static_results[]` — `status` passed/failed/error/skipped, `output_tail`.
* `remaining_references[]`, `unresolved_dynamic_references[]`, `static_findings[]`, `apply_errors[]`.
* `unresolved_risks[]`, `required_approvals[]`, `actions_not_taken[]` (always shown: nothing was merged or archived).
